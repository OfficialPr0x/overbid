# 10 — Milestones and agent handoffs

## M0 Inspect and contract
Read all specs and refs; inspect fresh project; choose compatible stack; record missing inputs. Establish copy/data/service contracts. Deliver tree and plan; do not burn asset budget yet.

## M1 Static visual system
Scaffold routes,fonts,tokens,header/footer and7 sections. Use supplied logo and staged clean plates when available; if not, clearly tracked temporary dark placeholders preserve composition. Actual generated clean art is required for final visual acceptance. Exit: complete desktop page screenshot,real copy,no screenshot-as-site shortcut.

## M2 Responsive and accessible
Implement named breakpoint behavior,mobile navigation,forms/cards,focus states and typography. Exit: matrix screenshots,no overflow,keyboard walkthrough,reduced-motion state.

## M3 Functional demo
Search/filter/details/bookmarks,draft wizard,introduction validation,about/legal placeholders. Exit: explicit sample/demo labels,working paths,no false submissions.

## M4 Assets and motion
Inspect KIE preflight; generate one hero plate then cohesive batch within authorized budget; optimize,compose logo separately; optional intro and ambient loop. Exit: no broken assets,poster fallback,performance budget and reduced-motion pass.

## M5 Hardening and handoff
Build/typecheck/lint,E2E and visual QA; fix substantive failures; report delivery evidence and unresolved owner launch inputs. No deployment implied.

## M6 Production integration (separate configured milestone)
Connect auth,database,listing review,private documents,lead destination,privacy/terms and operator identity. Enforce actual permissions. Replace sample inventory with approved listings. Validate transactions and readiness before publication.

## Workstream ownership if owner enables multiple agents
Integration owner: tokens,routing,dependencies,shared contracts and merges.
UI implementer: section components within approved contracts.
Asset implementer: art and provider tooling,never global page styling.
Marketplace implementer: filters,details,wizard and types coordinated with integration owner.
QA reviewer: independently executes checks and reports defects,not silent design edits.

Each handoff: scope,changed paths,prop/type contracts,assets used,tests/screenshots,known issues,next action. A handoff is reviewable work, not an instruction to overwrite another branch.
